# MediaTools 后处理工具链

## 1. 部署架构 (Deployment)

MediaTools 是一个媒体后处理工具集合，基于独立的 `mediatools-network` 网络运行，与 Servarr 核心管道解耦。包含以下核心组件：
- **SubtitleTranslator**: 字幕感知翻译与后处理。
- **AudioCleaner**: 媒体音轨智能清理。

数据逻辑分为三层：
- **服务自产层 (Service Local)**：`./config`, `./data`, `./logs` 等目录映射至 `./` 相对路径。
- **公共资源层 (AppData)**：无需依赖。
- **媒体资源层 (Resource)**：海量存储文件，映射至 `${RESOURCE}/Media`。

## 2. 快速启动 (Quick Start)

1. 检查全局配置：确保 `global.env` 中的时区、UID/GID 等基础变量正确。
2. 检查 `MediaTools.env` 中的局部变量，尤其是通过 `global.env` / `secrets/.env` 桥接的 LLM API 凭据。
3. 执行 Compose 部署：[MediaTools.yml](../../../Compose/MediaTools/MediaTools.yml)

> [!IMPORTANT]
> 部署前请确保已配置好 `secrets/.env` 并且全局环境变量被正确加载。

## 3. 详细配置参数表 (Configuration Table)

| 选项 | 值/变量 | 修改建议 | 说明 |
| :--- | :--- | :--- | :--- |
| **SubtitleTranslator** | | | |
| 容器命名 | `subtitle-translator` | 🟢 保持默认 | 服务主机名 |
| WebUI 端口 | `9800` | 🟡 根据需要 | 字幕翻译界面访问端口 |
| 代理环境 | 无 | 🟡 根据需要 | 如果请求 OpenAI 等海外接口超时，需考虑接入 `x-proxy-env` |
| **AudioCleaner** | | | |
| 容器命名 | `audiocleaner` | 🟢 保持默认 | 服务主机名 |
| WebUI 端口 | `9830` | 🟡 根据需要 | 音轨清理界面访问端口 |
| **公共配置** | | | |
| PUID/PGID | `1001/100` | 🟢 保持默认 | 与宿主机权限对齐 |
| 媒体资源 | `${RESOURCE}/Media` | 🔴 必须正确 | 必须与 OMV 挂载的资源池路径对应 |

## 4. 外部协作与优化 (Optimization)

- **权限管理**: 两个工具均以只读或相同用户权限访问媒体库，确保不会引发权限冲突。
- **依赖隔离**: 与 Servarr 无 API 级容器通讯，故障隔离性强。
